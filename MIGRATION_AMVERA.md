# NOYA CLUB — миграция Vercel → Amvera

**Обновление 14 ноября 2026:** приложение уже развёрнуто на Amvera, а действующая реальная оплата была включена по разрешению владельца. Старые нижеописанные пункты первоначального тестового переноса являются историческим планом и НЕ должны применяться повторно. Не изменяйте рабочие платёжные переменные и webhook при доработке функций.\n\n**Ветка:** feature/amvera-migration. Новая разработка добавляет первые шаги, дневник и проверку заданий, не затрагивая реальные платежи.

## Сохранённая архитектура

- **Supabase:** тот же проект, ученики, уроки, просмотры, личная библиотека, рейтинг, подписки и платежи. Дублировать или импортировать БД не нужно.
- **Cloudflare Stream:** тот же аккаунт и video ID; воспроизведение через временные серверные токены.
- **Telegram:** тот же бот @NoyaClubBrooksBot и обязательная серверная проверка подписи WebApp initData.
- **Prodamus:** существующая логика подписи webhook, сверка заказов и запись платежей в Supabase, новая ссылка callback нужна только при финальном переходе.
- **Vercel:** остаётся работающей тестовой резервной версией до одобренного переключения.

## Что изменено в GitHub

- server.cjs — Node 22 HTTP-сервер со всеми 11 API-обработчиками и 8 rewrite-маршрутами Vercel.
- amvera.yml — Node.js Server, npm start, HTTP-порт 3000.
- package.json — запуск на встроенном Node.js без сторонних пакетов.
- .env.example — имена конфигурационных переменных без реальных секретов.
- tests/amvera-server.test.cjs — HTTP, статика, проверка авторизации, старые адреса API, уведомления Prodamus.
- .github/workflows/amvera-ci.yml — автоматическое тестирование при обновлении ветки.

Публично раздаются только перечисленные HTML-страницы и файлы assets. Закрытые файлы api, lib, секреты и конфигурации не раздаются. Старые API-адреса сохранены, включая /api/club-checkout, /api/club-prodamus-webhook и /api/club-reward-pdf.

## Шаг 1. Создание тестового приложения Amvera

1. Открыть https://cloud.amvera.ru/projects → создать проект → Приложение.
2. Выбрать среду Node.js Server. Для первого тестирования возможен тариф «Начальный Плюс». Для 1000 участников потребуется отдельная проверка нагрузки.
3. В разделе «Репозиторий» подключить GitHub EvgeniyBrooks/zoohotelier-app, выбрать ветку feature/amvera-migration. НЕ использовать устаревшую main.
4. В разделе «Конфигурация» убедиться, что Amvera видит amvera.yml в корне, запускает npm start и слушает порт 3000.
5. В разделе «Домены» выдать публичный HTTPS-домен Amvera.
6. Добавить секреты и конфигурационные переменные только в разделе «Переменные» (см. ниже), запустить/перезапустить приложение.

Официальные руководства:
https://docs.amvera.ru/applications/environments/nodejs-server.html
https://docs.amvera.ru/applications/git/webhooks.html
https://docs.amvera.ru/applications/configuration/variables.html

## Шаг 2. Перенос переменных БЕЗ раскрытия секретов

Настройки и значения могут различаться для Preview и Production Vercel. Не копировать демо-значения в рабочую подписку. Никакие секреты не передавать через чат, GitHub, скриншоты или файлы проекта.

База и Telegram (обязательно):
- NEXT_PUBLIC_SUPABASE_URL — URL существующего Supabase.
- SUPABASE_SERVICE_ROLE_KEY — секретный ключ Supabase, только на сервере.
- NOYA_TELEGRAM_BOT_TOKEN — действующий токен бота.
- TELEGRAM_BOT_TOKEN — тот же токен для совместимости со старыми административными обработчиками.

Видео (обязательно для просмотра):
- CLOUDFLARE_ACCOUNT_ID
- CLOUDFLARE_API_TOKEN

ИИ (только после проверки связи):
- NOYA_AI_ENABLED=0 для первого запуска
- OPENAI_API_KEY — если планируется включить ИИ

Платежи (текущее рабочее состояние уже согласовано с владельцем):
- NOYA_PRODAMUS_ENABLE — СОХРАНИТЬ действующее значение Amvera
- NOYA_PRODAMUS_TEST_MODE — СОХРАНИТЬ действующее значение Amvera
- NOYA_PRODAMUS_DEMO_MODE — СОХРАНИТЬ действующее значение Amvera
- NOYA_PRODAMUS_FORM_URL — адрес действующей формы
- NOYA_PRODAMUS_SECRET — секрет подписи
- NOYA_PRODAMUS_SUBSCRIPTION_ID — действующий товар
- NOYA_CLUB_PRICE_RUB — действующая стоимость
- NOYA_CLUB_TERMS_URL — HTTPS-адрес /club-terms.html на новом домене
- NOYA_CLUB_RETURN_URL — HTTPS-адрес /club.html на новом домене

Дополнительно: NOYA_CLUB_ALLOW_PUBLISH=false, PORT=3000.
См. шаблон .env.example, там нет действительных ключей.

## Шаг 3. Техническая проверка БЕЗ оплаты

После успешной сборки заменить YOUR-AMVERA-DOMAIN на домен, созданный Amvera:

~~~bash
curl -i https://YOUR-AMVERA-DOMAIN/healthz
curl -I https://YOUR-AMVERA-DOMAIN/club.html
curl -I https://YOUR-AMVERA-DOMAIN/course-live.html
curl -I https://YOUR-AMVERA-DOMAIN/assets/noya-library.js
curl -i "https://YOUR-AMVERA-DOMAIN/api/club-checkout?status=1"
~~~

Ожидаем: /healthz = 200, club.html = 200, assets = 200. В ответе статуса оплаты должно быть enabled:false до включения реальных платежей. /server.cjs, /.env, /lib/* и /api/*.js должны возвращать 404.

Локальный запуск:
~~~bash
npm start
npm run test:amvera
~~~

Далее проверить запросы к Supabase и Cloudflare с самого контейнера Amvera. Реальная сетeвая связность из выбранного региона не гарантируется только успешным стартом Node.

## Шаг 4. Проверка в Telegram, без переключения рабочего бота

Проверить через Telegram WebApp (подписанный initData действующего бота):
- отображение подписки и даты доступа;
- 26 уроков курса, их прогресс;
- 3 эфира и защищённый просмотр Cloudflare Stream;
- историю, избранное и пройденные материалы;
- участников, рейтинг и добровольную публичность;
- PDF-подарки, если разрешён доступ;
- админку и сообщения об ошибках.

Тестовая HTTPS-страница в обычном браузере не сможет подтвердить авторизацию Telegram, это нормально. Не менять действующую ссылку Mini App до того, как проверены альтернативные тестовые кнопки или согласован финальный переключатель.

## Шаг 5. Оплата — отдельное согласование перед запуском

Сначала тестировать Prodamus demo/test и подписанный webhook. Проверить, что подтверждённый платёж появляется один раз, повторное уведомление не даёт повторного начисления, статус подписки верный.

После успешной проверки:
1. Настроить в Prodamus URL уведомлений https://YOUR-AMVERA-DOMAIN/api/club-prodamus-webhook.
2. Сверить уже действующие ссылки возврата и условий подписки с текущим HTTPS-доменом Amvera.
3. Сохранить включённые по разрешению владельца реальные платежи и действующие значения переменных; не переключать тестовый режим без отдельного нового указания.
4. Проверить, что действующая ссылка Telegram Mini App ведёт на проверенный адрес Amvera.
5. Проверить реальный платёж, доступ и отмену продления.
6. Оставить старую версию на Vercel для отката.

Переключение webhook и Telegram Mini App НЕ включено в подготовку ветки и требует отдельного решения владельца.

## Масштабирование и безопасность

Видео остаются на Cloudflare, файлы данных — в Supabase, поэтому контейнер Amvera обслуживает страницы и API. Нужен нагрузочный тест (50/100/200 одновременных пользователей), мониторинг ошибок и расхода ресурсов. У Amvera входящий трафик тарифицируется отдельно и может ограничивать размер запроса/ответа, тайм-аут, соединения и число запросов в минуту.

Проверьте юридические требования к обработке персональных данных граждан РФ. Сам перенос HTTP-сервера в РФ не перемещает базу Supabase.

## Откат

При проблемах вернуть ранее проверенную ссылку в Telegram и старый адрес уведомлений Prodamus; отключить реальные платежи на новом сервере до устранения причины. Supabase и Cloudflare не удалять, токены наугад не менять.
